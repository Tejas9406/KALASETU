# KALA SETU 2.0 — MASTER PROMPT: THE DUAL-DOMAIN GLOBAL CULTURAL INTELLIGENCE PLATFORM

## *"From Local Artisans to a World of Living Heritage"*

---

## 0. CONTEXT — READ THIS FIRST

### What Exists

**KALA SETU is already built and working.** It is a functional full-stack platform with:

- Complete Node.js + Express + TypeScript backend
- Complete React + Vite + TypeScript frontend
- Live Neon PostgreSQL database
- Active Upstash Redis cache
- Cloudinary media storage
- Multi-provider AI (Gemini + OpenAI + Groq)
- Voice input, multi-lingual support
- MapLibre maps, Razorpay test payments
- SOS emergency system
- Government dashboard
- AI Cultural Concierge

**This project works. It is not a prototype.**

### The Problem

A senior reviewer said: **"Your project looks like normal software — like you built it 5 years ago. Today is the AI/ML era. They want extraordinary AI/ML — many concepts, not just RAG and semantic search."**

He is partially right. The AI/ML exists, but it is **hidden in backend logs**, **invisible to the user**, and **indistinguishable from any other RAG+chatbot project**.

### The Mission

**Reform the existing project — do not rebuild it.**

Transform KALA SETU into a **dual-domain cultural intelligence platform** where:

1. **Local Artisans** and **Local Community Experiences** become two first-class worlds
2. Each world has its **own AI/ML intelligence** — not one generic engine pretending everything is the same
3. The platform is **designed for global expansion** — not "India with more countries"
4. Every AI/ML operation is **visually undeniable** — no more hiding in logs
5. The **Genesis module** proves the effort — ethnographic research, architecture, everything

```
    ├── food
    ├── dances
    ├── music
    ├── cultural practices
    ├── locations
    ├── seasons
```

## 8. TWO DIFFERENT ADVANCED AI/ML SYSTEMS

### 8.1 Artisan Intelligence

| # | System | Description | Technology |
|---|--------|-------------|------------|
| 1 | **Multimodal Craft Recognition** | Photo → identify craft/material/style → find relevant artisans | CLIP + ViT (fine-tuned on craft dataset) |
| 2 | **Skill/Technique Analysis** | Video → pose/motion analysis → technique assistance signal | MediaPipe (33 landmarks, joint angles, velocities) |
| 3 | **Artisan Recommendation** | User preferences + craft similarity + distance + trust + availability → ranking | Feature-weighted ranking (later: learned ranking model) |
| 4 | **Artisan Demand Forecasting** | Historical views + bookings + seasonality + location → future demand | Time-series Transformer |
| 5 | **Anomaly Detection** | Suspicious review bursts, abnormal listing behavior, duplicate content | Isolation Forest + Autoencoder |

**Important:** Skill/Technique Analysis should **never claim that movement alone proves authenticity**. It is an assistance signal only.

### 8.2 Community Intelligence

| # | System | Description | Technology |
|---|--------|-------------|------------|
| 1 | **Cultural Semantic Understanding** | Query → food + music + tradition → relevant destinations | Semantic retrieval + knowledge graph |
| 2 | **Cultural Knowledge Graph** | Region → Community → Festival → Food → Music → Dance → Historical Context → Experience | Neo4j / GraphRAG |
| 3 | **Seasonal Intelligence** | Festival calendar + weather + historical demand + availability → suitability | Time-series + calendar integration |
| 4 | **Cultural Experience Recommendation** | Traveler profile + destination + season + interests → ranking | Hybrid recommender |
| 5 | **Crowd/Pressure Intelligence** | Demand + capacity → crowding indicator → recommendation adjustment | Load-balancing algorithm |

UNESCO explicitly links living heritage with sustainable development and community resilience. Crowd/Pressure Intelligence supports this direction.

## 9. THE GLOBAL WORLD

**Design as a global platform from the beginning.** Initially activate only selected Indian data.

### 9.1 Universal Location Hierarchy

Do **not** hardcode `Country → State → District`. Administrative structures differ between countries.

Use:
```
COUNTRY
   ↓
ADMIN_REGION_LEVEL_1
   ↓
ADMIN_REGION_LEVEL_2
   ↓
LOCALITY
```

Each region has:
- id, country_code, parent_id
- name, local_name, admin_level
- iso_code, latitude, longitude

ISO 3166 provides universally applicable coded representations of country names and subdivisions. ISO 3166-1 (country codes) and ISO 3166-2 (subdivision codes) provide the standard foundation. Over 4,000 subdivision codes are defined globally.

### 9.2 Global Coverage States

Every country/region has a clear status:

```
India
🟢 Available

Japan
🟡 Preview available

Italy
🟡 Selected cultural data available

Brazil
⚪ Coming Soon
```

Never make empty pages look broken. Show available static experiences. Where data isn't ready: **Coming Soon** with explanation.

### 9.3 Global Data Must Be Source-Aware

Every cultural item has:
```
Source, Source Type, Source URL
Country, Region, Community
Last Verified, License, Contributor
Confidence
```

**Source hierarchy (configurable):**
| Tier | Source Type |
|------|-------------|
| 1 | Official national/regional sources |
| 2 | UNESCO / international cultural datasets |
| 3 | Recognized institutions / museums / universities |
| 4 | Community-provided information |
| 5 | Curated secondary sources |

**Do not let AI invent cultural facts.** AI-generated text must never be presented as community-authenticated fact.

### 9.4 Global Media Separation

## 14. AI/ML IMPLEMENTATION — ARTISAN

### 14.1 Craft Recognition (Multimodal)

**Stack:** CLIP + ViT (fine-tuned on craft dataset) or Gemini Vision (fallback)

```
Image
 ↓
Vision Model (ViT encoder)
 ↓
Embedding / Classification
 ↓
Craft Candidates (top-K)
 ↓
PostgreSQL metadata
 ↓
Confidence
 ↓
Artisan Results
```

Research shows CLIP baseline struggles with domain-specific distinctions in intangible cultural heritage, with significant overlap between embroidery, weaving, and batik clusters. Fine-tuned models achieve clear category-wise clustering.

### 14.2 Skill/Technique Analysis (Kinematic)

**Stack:** MediaPipe Pose (33 body landmarks)

```
Video
 ↓
Pose Extraction (MediaPipe — 33 landmarks per frame)
 ↓
Feature Extraction (joint angles, velocities, accelerations)
 ↓
MLP / LSTM Model
 ↓
Technique Analysis
 ↓
Assistance Signal (never authenticity proof)
```

MediaPipe provides production-ready ML solutions for pose estimation, optimized to run in real-time on mobile devices, web browsers, and desktops.

### 14.3 Artisan Recommendation

```
Candidate Generation (PostgreSQL + Chroma)
 ↓
Feature Calculation (similarity, distance, availability, verification, rating, budget_fit, duration_fit, interest_match, accessibility_match)
 ↓
Ranking (feature-weighted)
 ↓
Recommendation
```

Later: replace hand-designed weights with learned ranking model when enough interaction data exists.

### 14.4 Demand Forecasting

**Stack:** Time-series Transformer (Encoder-Decoder architecture)

Tourism demand forecasting with Transformers encodes long-term dependencies with the encoder, merges calendar data points in the forecast horizon, and captures short-term dependencies with the decoder. Hybrid BiLSTM + Transformer models address both short-term fluctuations and long-term trends.

### 14.5 Anomaly Detection

**Stack:** Isolation Forest + Autoencoder

Detect:
- Suspicious review bursts
- Abnormal listing behavior
- Duplicate content
- Unusual booking patterns

**Output:** "Review this listing" — not automatic accusation.

## 15. AI/ML IMPLEMENTATION — COMMUNITY

### 15.1 Cultural Knowledge Graph

**Stack:** Neo4j + GraphRAG

Entities:
```
Country, Region, Community, Culture, Tradition
Festival, Food, Dance, Music, Material
Place, Season, Experience
```

Relationships:
```
PRACTICED_IN, ASSOCIATED_WITH, CELEBRATED_DURING
ORIGINATES_FROM, USES, PERFORMED_AT, AVAILABLE_IN, RELATED_TO
```

GraphRAG combines vector search with knowledge graph query to retrieve contextual data that better reflects the interconnection of data from various sources.

### 15.2 Knowledge Graph Neural Network

**Stack:** Knowledge Graph Attention Network (KGAT)

Research shows KGAT combining collaborative knowledge graph with Graph Attention Network enables personalized heritage recommendation, addressing cold-start problem and enabling discovery.

### 15.3 Cultural RAG

```
Question
 ↓
Intent Classification
 ↓
Location Extraction
 ↓
Community Vector Search (Chroma community_knowledge)
 ↓
Knowledge Graph Lookup (Neo4j)
 ↓
PostgreSQL Validation
 ↓
LLM (Gemini/Groq/OpenAI)
 ↓
Answer with Sources
```

This becomes **Graph + RAG**, not basic RAG.

### 15.4 Seasonal Intelligence

```
Festival Calendar
+ Weather/Season

+ Local Availability
        ↓
Experience Suitability
```

### 15.5 Crowd/Pressure Intelligence


## 18. ADVANCED AI/ML — THE COMPLETE STACK

### 18.1 Artisan AI Stack

| Layer | Technology | Purpose |
|-------|------------|---------|
| **Perception** | CLIP + ViT | Craft recognition from images |
| **Perception** | MediaPipe | Skill/technique analysis from video |
| **Reasoning** | KGAT | Artisan-craft relationship reasoning |
| **Reasoning** | RAG (Chroma) | Artisan knowledge retrieval |
| **Prediction** | Time-series Transformer | Demand forecasting |
| **Prediction** | Isolation Forest | Anomaly detection |
| **Privacy** | Federated Learning | Privacy-preserving artisan recommendations |
| **Explainability** | SHAP + LIME | "Why this recommendation?" |

### 18.2 Community AI Stack

| Layer | Technology | Purpose |
|-------|------------|---------|
| **Perception** | CLIP + ViT | Cultural experience image understanding |
| **Reasoning** | GraphRAG (Neo4j) | Cultural knowledge graph traversal |
| **Reasoning** | KGAT | Community-culture relationship reasoning |
| **Prediction** | Time-series Transformer | Seasonal demand forecasting |
| **Prediction** | Load-balancing algorithm | Crowd/pressure intelligence |
| **Privacy** | Federated Learning | Privacy-preserving cultural recommendations |
| **Explainability** | SHAP + LIME | "Why this experience?" |

### 18.3 Federated Learning

Phase-Adaptive Federated Learning (PAFL) dynamically balances privacy and utility through a phase-dependent aggregation mechanism. Experimental results demonstrate 18.7% higher HR@10 and 62% lower membership inference risk compared to state-of-the-art methods.

### 18.4 Explainable AI

Integrate SHAP and LIME to disentangle model decisions. Research shows a 3% increase in recommendation precision when incorporating explainability techniques, with notable increase in user ability to understand and trust suggestions.
